# Decisions

- Handle table: `vector<Entry> by_handle` (index = offset) + `unordered_map<void*,unsigned> by_ptr` keyed on family base pointer. 20-bit index + 11-bit generation, handle never 0.
- Type tags are per FAMILY (HT_ENTITY, HT_STREAM, HT_TCP_SERVER, etc.), not per class. `handle_type_tag<T>` maps each subclass to its family.
- Pointer normalisation: store and key by_ptr on the family BASE pointer (Entity*, bbStream*). `bbH<T>` converts T*→Base* in, `static_cast<T*>(static_cast<Base*>(vp))` out. Never static_cast from void*.
- Windows: `BB_HANDLE(T)` is plain `T*`. No struct, no table. Zero behavioural change.
- Validation uses the runtime `debug` flag (same as debugEntity/debugTexture), not #ifdef DEBUG. Release: invalid handle → null.
- `forget()` lives in family base destructors we own (~Entity, ~bbStream, ~Surface, ~Texture, ~Brush, ~bbImage, ~bbBank, ~Sound). Wrapper-side forget only for gx-owned objects (font, movie, dir, timer, canvases).
- Texture/Brush use ref-counted Rep; forget() goes in ~Texture/~Brush (outer object), not ~Rep. Surface forget in ~Surface covers MeshModel::Rep::~Rep path.
- Canvas forget: bbImage frames in ~bbImage; texture canvases in CachedTexture::~CachedTexture; front/back via explicit forget() in bbEndGraphics/bbGraphics.
- Soloud backend channels are already 32-bit ints — no handle wrapping needed.
- `sem_env` fix: minimal `DebugEnvTable` (int id → pointer) in bbruntime, populated at load time.
- Testing: C++ unit tests calling bb* functions directly (.bb programs can't run until x86-64 codegen + loader exist). Build: `cmake --build build -- -k 0`.
- Commit sequence: 9 commits, core+tests first, then pilot (bbbank), then by module, ~5 files max per commit.
- `forget()` sets `base_ptr = 0` to mark slot free; generation persists for wrap (2047→1). Free-slot detection is `base_ptr == 0`, not `generation == 0`.
- Type specialisations split into `bb_handle_types.h` (included after real type definitions) to keep the core header self-contained for unit tests.
- Error hook: `void (*bb_handle_error)(const char*)` — null by default, set by bbruntime init to call RTEX, or by tests to a recorder. Called when `bb_handle_debug && bb_handle_error` on stale handle / type mismatch / capacity exceeded.
- `bb_handle_debug` mirrors bbruntime's `debug` global (bbsys.h). Set by bbruntime init or directly in tests.
- Free list: singly linked through `next_free` field of free entries, head = `free_list_head`. Capacity check: index > 0xFFFFF → error hook.
- Vector starts with one dummy entry at index 0 (reserved). First real allocation gets index 1.
- bbbank pilot: BB_HANDLE wrappers on all 16 bank rtSym signatures. `bbFreeBank` takes BB_HANDLE, converts to raw pointer via `bbBank *b=h`. `bank_destroy()` wraps raw pointer in BB_HANDLE before calling bbFreeBank.
- bbruntime_run wires `bb_handle_debug = dbg` and `bb_handle_error = handle_error_rtex` (calls RTEX). Guarded with `#ifndef _WIN32`.
- Userlib `'*'` params (struct types): compiler emits IR_MEM to load raw pointer from variable. On macOS this loads a 4-byte handle. Needs handle lookup in codegen — deferred.
- Windows cast fix: `BB_HANDLE(T)(x)` is invalid on _WIN32 (becomes `T*(x)`). Use implicit conversion (`return b;`) instead. RTSYM_CAST macro for rtSym function pointers: identity on _WIN32, `(void*)(f)` on non-Windows.
- gxruntime_b3d.h macOS compatibility: guard all Windows-only includes/members with `#ifdef _WIN32`, forward-declare classes (gxAudio, gxInput, etc.) on non-Windows. No behaviour change on Windows.

- x64 c5: tiles are a stack evaluator (result in rax, right operand pushed, popped into rcx); only rax/rcx/rdx used, so no callee-saved registers. m_depth tracks pushed bytes for commit 6 call alignment.
- x64 c5: width = isWide(): MEM/CALL/MOVE use the wide tag, LOCAL/GLOBAL/ARG wide, ADD/SUB/MUL/DIV/AND/OR/XOR wide if either side is (narrow side sign-extended with movsxd), shifts/NEG follow the left operand, relops compare at the wider width.
- x64 c5: JUMPGE targets are always runtime error routines (__bbArrayBoundsEx, __bbVecBoundsEx): emitted as jb skip; movabs rax,sym (ABS64); jmp rax. They are entered with rsp 16-aligned, not call-aligned; commit 6/10 must make those routines safe for that (noreturn, no SSE-aligned spills) or switch to a call.
- x64 c5: frame is push rbp / mov rbp,rsp / sub rsp,align16(frameSize); locals [rbp-8*(k+1)]; argOffset is provisional [rbp+16+8*k] until commit 6 picks the Blitz->Blitz convention. leave() pop_sz ignored until commit 6.
- x64 c6: two call conventions. C calls (sconst "C"+classes): System V, args written to the outgoing area by the IR then loaded into rdi..r9 / xmm0..7 (movd from the 32-bit slot), overflow args copied in order to [rsp+8*j] below the area via r11. Blitz calls (sconst ""): area left at [rsp], callee params at [rbp+16+8*k], caller frees, leave() ignores pop_sz. Why: IR floats are untyped bit patterns and enter() has no param types, so System V homing in Blitz callees would need new front-end plumbing; Blitz functions are never called from C except the 0-arg main.
- x64 c6: int args to C keep garbage in the upper 32 bits of the register/stack slot (SysV leaves them undefined for int params). Wide args are full 64-bit.
- x64 c6: every call is padded so rsp%16==0 at the call (m_depth counts pushes + areas). JSR is `sub rsp,8; call; add rsp,8` so Gosub bodies stay aligned. JUMPGE error routines are now *called* (aligned, never return) instead of jumped to — supersedes the c5 note.
- x64 c6: call targets always go through `movabs rax,sym; call rax` (ABS64), Blitz functions included. A direct rel32 for same-module calls is a later optimisation.
- x64 c7: floats are evaluated into xmm0 by evalF(); the parent node decides float context (the IR has no float type, float constants are CONST holding the bits). In int context FADD..FDIV/FNEG/FCAST/FCALL run evalF then movd eax,xmm0, so storing a float to a local is the ordinary 32-bit int MOVE. Single precision only.
- x64 c7: float temporaries use fpush/fpop = sub rsp,8 + movss [rsp] / movss + add rsp,8, with m_depth +/-8. Never [rbp-N]: that is where the locals live (the first local-model attempt stored temporaries there and corrupted nested expressions).
- x64 c7: IR_CAST (float->int) is cvtss2si (round to nearest even under default MXCSR: 2.5->2, 3.5->4, -2.5->-2). FCAST is cvtsi2ss from eax.
- x64 c7: FSETxx = ucomiss l,r then setcc; ucomiss sets CF/ZF like an unsigned compare, so EQ=kE, NE=kNE, LT=kB, GT=kA, LE=kBE, GE=kAE (one fcond() shared by eval and condJump). NaN/PF is not special-cased.
- x64 c7: leave() saves rax and xmm0 around the cleanup statement, because the cleanup may call C and clobber both. Blitz and C functions both return floats in xmm0, so callNode needed no change for FCALL.
- x64 c7: SSE single precision can differ in the last bit from x87 results on Windows.
- x64 c7: scope note: tests/x64/x64test.h (fret/fcallN helpers) and tests/x64/test_tiles_x64.cpp (the "FADD unsupported" error check now uses opcode 9999, count stays 167) were edited with the user's approval.
- x64 c8: bbruntime/basic.h is `#pragma pack(1)`, so BBObj (36 bytes), BBObjType (type@0, used@4, free@40, fieldCnt@76, fieldTypes@80), BBVecType, BBArray and BBData (12 bytes: int + 8-byte BBField) have NO padding even on x86-64. This supersedes the plan's "padding matching the runtime layout": the correct padding is none.
